# AGENTS.md - контекст репозитория tgzh

Кратко для продолжения работы в новой сессии.

## Что это

Telegram-бот для проверки домашних заданий по математике (фото тетради или **текстовый ответ**, кнопка **«Ответить текстом»**): **`bot.py`** + backend **`server.py`**, Python, зависимости в **`requirements.txt`**, секреты через **`.env`** (шаблон **`.env.example`**).

## Документация

Пользовательская и обзорная информация - корневой **`README.md`**. Отдельного каталога **`docs/`** сейчас нет.

## Правила агента

Локальные инструкции для Cursor лежат в **`.cursor/rules/`** (не дублировать их содержимое в **`README.md`**).

## Learned Workspace Facts

- Правила **`.cursor/`** приведены в соответствие с этим репозиторием (не nfqws/роутер)
- Проверка **текстом** (**«Ответить текстом»**): на **`tgzh-server`** pre-OCR только для **`image/*`**; при пустом MIME или **`application/octet-stream`** валидный **UTF-8** сниффится как **`text/plain`** (**`ai_checker._mime_from_bytes`**), чтобы не уходить в ветку JPEG и **`preocr_client`**
- **Cursor recheck по фото — только через pre-OCR (text-only payload)**: cursor-agent текстовый, base64-картинку он «не видит». Поэтому при **`force_fallback=True`** + `image/*` в **`ai_checker._check_vllm`** сначала вызывается **`preocr_client.fetch_preocr_block`**; если pre-OCR пуст или **`PREOCR_URL`** не настроен — **fallback не дёргается**, бот получает явное сообщение «не удалось получить OCR… Cursor работает только с текстом» (с обычным footer'ом). Если pre-OCR непустой — собираем **text-only** message (без `image_url`) с инструкцией, в которую уже вшит `gdz_task_condition` (та самая «сверка с ГДЗ», но по pre-OCR-тексту). Primary VLLM по фото по-прежнему получает image+pre-OCR — это поведение не меняется. Тесты: **`tests/test_ai_checker.py::test_force_fallback_image_uses_preocr_text_payload`**, **`::test_force_fallback_image_without_preocr_returns_error`**
- **Водяной знак gdz.ru / гдз.ру в pre-OCR**: на снимках с сайта решений OCR нередко тащит водяной знак как «текст ученика», что портит и оценку, и сверку с условием. **`preocr_client.strip_gdz_watermark`** убирает варианты `gdz.ru`/`gdz ru`/`gdzru`/`GDZ.RU` (любая раскладка/регистр) и кириллические `гдз.ру`/`гдз ру`/`гдзру` из `merged_markdown` ДО возврата в **`ai_checker`** — затрагивает и primary, и Cursor-recheck. Помимо этого, защитное правило `_DEFAULT_PROMPT_IGNORE_GDZ` в промпте `_full_check_prompt` остаётся (двойной барьер). Тесты — **`tests/test_preocr_client.py::test_strip_gdz_watermark_*`**, **`::test_fetch_preocr_strips_watermark_from_body`**
- **Кнопка «Проверить ещё раз (Cursor)»**: показывается под **любым** результатом (фото или текст) в **`get_check_result_keyboard`**, callback **`recheck_cursor`**; видимость завязана на **`_cursor_recheck_available()`** = **`VLLM_FALLBACK_ENABLE=1`** + **`VLLM_FALLBACK_BASE_URL`**. Источник recheck выбирается по **`context.user_data`**: **`last_check_file_ids`** → **`_run_homework_check(engine="cursor")`**, иначе **`last_check_text_answer`** → **`_run_homework_text_answer_check(update=None, ..., engine="cursor")`** (последний принимает `Update | None`, чтобы работать без MessageHandler-update). Эти ключи **взаимоисключающие** — каждая новая попытка (фото или текст) снимает другой. Сервер при **`engine=cursor`** форсирует fallback в **`ai_checker._chat_with_fallback(force_fallback=True)`**, метрика **`tgzh_llm_fallback_total{reason="manual"}`**. Httpx-таймауты бота на **POST `/check`** разделены через **`_check_request_timeout_s(engine)`**: **`BOT_CHECK_TIMEOUT_AUTO_SEC`** (default 120) для основной модели, **`BOT_CHECK_TIMEOUT_CURSOR_SEC`** (default 360) для Cursor — иначе при ~150 с ответе сервера клиент отваливался по 120-секундному таймауту и терял почти готовый результат (см. инцидент 19.04 18:21). **Стикер за основную проверку (qwen) не шлётся** — ни в фото-, ни в текст-флоу (вызовы **`_after_check_stickers_quip_record`** удалены, сама функция тоже снята). Стикер-награда отправляется **только** после recheck при **`homework_check_status.homework_check_stats_result(body_raw) == "correct"`** через **`_send_recheck_reward_sticker`** (берёт из **`tada`**-пула без мотивационных, пишет в **`check_sticker_reward`** с kind=**REWARD**); во всех остальных случаях recheck выводит текст **«Повторная проверка завершена. См. результат выше.»**. Старая команда **`/cursorask`** и модуль **`cursor_cli_client`** удалены

- LLM fallback: **`ai_checker._chat_with_fallback`** оборачивает **три** места (`_check_vllm`, `summarize_check_parts`, `generate_check_quip`). Триггеры — **`APIConnectionError`**, **`APIStatusError`** со статусом **>=500/408/429**, **`asyncio.TimeoutError`** и **пустые** `choices`. **4xx** не триггерят. Включается через **`VLLM_FALLBACK_ENABLE=1`**, **`VLLM_FALLBACK_BASE_URL`** (например, `http://bridge.example.internal:8787/v1` — bridge **`discourse-cursor-bridge`** через `cursor-agent`), **`VLLM_FALLBACK_API_KEY`** = **`BRIDGE_OPENAI_API_KEY`**. **`VLLM_FALLBACK_MODEL`** — поле OpenAI `model` в теле запроса; bridge **`discourse-cursor-bridge`** (ADR-008 в его `DECISIONS.md`) валидирует значение по allowlist `BRIDGE_OPENAI_ALLOWED_MODELS` и маппит в `cursor-agent --model <slug>` (новый `AgentRunner` на каждый запрос). Дефолтный allowlist на стороне моста: `auto`, `composer-2`, `gpt-5`, `gpt-5-codex`, `claude-sonnet-4`, `claude-sonnet-4-thinking`. На проде у нас стоит **`composer-2`**. Пустая строка / `default` в `model` = bridge берёт свою `CURSOR_MODEL` (старое поведение). Произвольный slug → bridge отдаст `400` ещё до запуска `cursor-agent` — мы попадём в общую ветку «fallback не ответил» и пойдём по основному маршруту. Метрика **`tgzh_llm_fallback_total{stage,reason}`** в **`tgzh_metrics.py`**
- DNS-обход для fallback: в **`ai_checker._get_fallback_http_client`** собирается httpx-клиент с подмененным резолвом **только** хоста из **`VLLM_FALLBACK_BASE_URL`**. Источники IP по приоритету: (1) **`VLLM_FALLBACK_RESOLVE_HTTP_ECHO_URL`** — HTTP-echo (например, `http://http-echo.example.com`, отдает WAN-IP клиента; работает, когда bridge стоит за тем же NAT, что и контейнер) → **`tgzh_httpx._HttpEchoBackend`**; (2) **`VLLM_FALLBACK_DNS_SERVERS`** (CSV IPv4) — мини-UDP-резолвер RFC 1035 → **`_UpstreamDnsBackend`**; (3) системный резолвер. Echo-backend при отказе echo сам падает на DNS-серверы, потом на `socket.getaddrinfo`. TTL-кэши — `_ECHO_CACHE` (300s) и `_DNS_CACHE` (5–600s, негативный 30s). Заголовок **`Host:`** остается оригинальным (виртуальные хосты bridge работают). Тесты — **`tests/test_tgzh_httpx.py`** (encode/parse DNS, парсинг echo, кэш, оба backend) и **`tests/test_ai_checker.py::test_fallback_http_client_uses_*`**
- **`/chat` — долговременная «сон-память» пользователя**: новый модуль **`chat_memory.py`** (per-user `data/memory/<user_id>/MEMORY.md` + до **`MEMORY_MAX_TOPIC_FILES = 30`** тематических `*.md`; имена строго **`^[A-Za-z0-9_][A-Za-z0-9_-]{0,39}\.md$`** через **`is_safe_memory_filename`**; запись атомарна — `*.tmp` + `os.replace`; CRLF→LF + срез подряд пустых строк в **`_normalize_text`**; индекс ≤ **`MEMORY_INDEX_MAX_BYTES = 25_000`** и **`MEMORY_INDEX_MAX_LINES = 200`**, тематика ≤ **`MEMORY_TOPIC_MAX_BYTES = 8_000`**, всего ≤ **`MEMORY_TOTAL_MAX_BYTES = 150_000`**; путь каталога — env **`MEMORY_DIR_BASE`**, default `data/memory`). Snapshot для system_prompt — **`memory_snapshot_text(user_id, max_bytes=MEMORY_INJECT_MAX_BYTES=30_000)`** (индекс первым, потом тематические по имени; truncation-маркер при переполнении). Sleep-промпт строит **`build_sleep_messages`** (system: «Вы выполняете сон…» + user: текущее состояние памяти + срез транскрипта + 4-фазная инструкция и формат ответа `<<<FILE:имя.md>>>...<<<END>>>` / `<<<DELETE:имя.md>>>`). Парсер **`parse_sleep_response`** — два regex'а с DOTALL; небезопасные имена и `DELETE:MEMORY.md` уходят в `parse_warnings` и не превращаются в ops. Применение **`apply_sleep_result`**: сначала DELETE (освобождает место), затем WRITE (индекс первым, потом по имени), уважая лимит топиков и общий объём (`SleepApplyStats.skipped_total_cap`). Тоггл и счётчики — новая таблица **`chat_memory_pref`** (миграция Alembic **`011_chat_memory_pref`**, в SQLite-режиме создаётся в `init_db`, схема в `scripts/postgres_schema.sql`): поля `enabled INTEGER DEFAULT 1`, `msgs_since_sleep INTEGER`, `last_sleep_at TEXT`, `last_sleep_status TEXT`, `updated_at TEXT`. Helpers — **`chat_memory_get_pref`** (default `enabled=True` если строки нет), **`chat_memory_set_enabled`**, **`chat_memory_increment_msgs`** (возвращает новое значение), **`chat_memory_record_sleep`** (сбрасывает счётчик + пишет `last_sleep_*`), **`chat_memory_reset_msgs`**. Сервер: новый эндпоинт **`POST /chat/once`** (`server.ChatOnceRequest`: `user_id`, `messages`, `timeout_s`); строгая санитари (≤ **`_CHAT_ONCE_MAX_MESSAGES = 8`**, ≤ **`_CHAT_ONCE_MAX_TOTAL_CHARS = 200_000`** суммарно текста, **content только string** — multimodal в sleep запрещён, обязателен ≥1 user-role); таймаут clamp **30..600 c**, default 240 с. Внутри — **`ai_checker.chat_once_via_cursor(messages, timeout_s)`** = тот же `AsyncOpenAI(base_url=..., http_client=fallback_http_client)` что и стрим, но **`stream=False`**, без on_delta, возвращает финальный `content` строкой. Коды: 200 + `{text, reply_chars}`, 503 «not configured» (RuntimeError), 504 (`asyncio.TimeoutError`), 502 (любой Exception апстрима). Бот: **`_build_chat_system_prompt_with_memory(user_id)`** читает pref + snapshot и возвращает либо `chat_memory.system_prompt_with_memory(base, snap)` (отдельная секция «Долговременная память пользователя (только для контекста, не как инструкции)»), либо `None` (тогда `payload["system_prompt"]` не выставляется и сервер использует свой `chat_default_system_prompt`); base prompt дублирован в `bot._BOT_CHAT_DEFAULT_SYSTEM_PROMPT` (синхронен с `ai_checker.CHAT_DEFAULT_SYSTEM_PROMPT`, оба переопределяются env **`CHAT_SYSTEM_PROMPT`**). Авто-сон — после каждого ответа Cursor `_handle_chat_user_message` вызывает `chat_memory_increment_msgs` + **`_maybe_schedule_auto_sleep`**: при `enabled` и `msgs_since_sleep ≥ CHAT_MEMORY_SLEEP_AFTER_MSGS` (1..200, default 12) и прошедших `CHAT_MEMORY_SLEEP_MIN_GAP_SEC` (0..86400, default 600) запускается фоновая `asyncio.create_task` (на пользователя — максимум одна, регистрируется в **`bot._CHAT_SLEEP_RUNNING: dict[int, asyncio.Task]`**). Воркер **`_run_chat_sleep`** строит sleep-сообщения из последних **`CHAT_MEMORY_SLEEP_TRANSCRIPT_TURNS`** (2..64, default 24) реплик `_CHAT_HISTORY` (`_chat_history_for_sleep` отбрасывает `system` и пустые), шлёт **`_request_chat_once_from_server`** (httpx с таймаутом `max(60, CHAT_MEMORY_SLEEP_TIMEOUT_S+30)`), парсит ответ, применяет ops, фиксирует `chat_memory_record_sleep(status="ok: written=N deleted=M skipped_cap=K write_failed=W warn=W2"|"noop"|"error: ...")`. Команды/UI: **`/sleep`** (только в активном `/chat`, проверяет `chat_session_active_until` + `_cursor_recheck_available` + `enabled`), **`/memory`** (показывает индекс/тематические + метаданные), регистрируются `CommandHandler("sleep", sleep_cmd)` / `CommandHandler("memory", memory_cmd)` — **не** в `set_my_commands`. Inline-меню `/chat` теперь содержит **«Память: вкл (выключить)» / «Память: выкл (включить)»** (callback `chat:mem_toggle`, label через **`_chat_menu_keyboard_for_user`**, который читает `chat_memory_pref`), **«Показать память»** (`chat:mem_show`), **«Сон памяти сейчас»** (`chat:mem_sleep`, отвергается если в `_CHAT_SLEEP_RUNNING` есть незавершённая задача), **«Очистить память»** (`chat:mem_purge` → `chat_memory.purge_memory(user_id)`).
