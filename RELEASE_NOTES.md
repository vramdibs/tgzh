- **Режим long-polling для Telegram (`TG_MODE=polling`)**: переключатель `TG_MODE` в `.env` (`webhook` по умолчанию, `polling` - обход при недоступном inbound HTTPS-вебхуке). В polling-режиме бот снимает webhook при старте и получает апдейты через исходящий `getUpdates`

Дефолт — `composer-2.5`; при недоступности на bridge автоматический retry на `cursor-grok-4.6-low`. Выбор хранится в `chat_memory_pref.chat_model_slug` (миграция Alembic `014_chat_model_slug`). Поле `model` в `POST /chat/stream` и `/chat/once`; `ai_checker.stream_chat_via_cursor` / `chat_once_via_cursor` пробрасывают slug в OpenAI `model`. Bridge allowlist дополнен `composer-2.5` и `cursor-grok-4.6-low`. Env: `CHAT_CURSOR_MODELS`, `CHAT_CURSOR_MODEL_DEFAULT`, `CHAT_CURSOR_MODEL_FALLBACK`. Доступ по-прежнему через `CHAT_PASSWORD` / `ADMIN_PASSWORD`. Тесты — `tests/test_chat_streaming.py`, `tests/test_chat_model_pref.py`.

- **Мультипредметные ДЗ**: бот и web поддерживают математику, алгебру, геометрию, русский язык и физику. Каталог — `data/gdz_catalog.json`; скрипт `scripts/fetch_gdz_textbooks.py --all`. Профиль пользователя — по строке на `(user_id, subject_slug)` + `user_settings.active_subject_slug`. В боте: выбор предмета, кнопки «Сменить предмет» / «Сменить учебник». `POST /check` и сводка принимают `subject_slug`; промпты в `ai_checker.py` по предмету. Web motok: select предмет/класс/учебник, `HomeworkPrefsBook`. Миграция Alembic `013_user_profile_multi_subject`. Тесты — `tests/test_user_storage_subjects.py`, motok `tests/test_homework_prefs.py`.

- **Фото-ответ на ДЗ имеет приоритет над лениво «оживающим» `/chat`**: если ученик нажал «Отправить фото» в режиме проверки ДЗ, отправленное фото теперь **всегда** уходит в проверку, а не описывается чат-ботом. Раньше после рестарта бота `/chat`-сессия лениво поднималась из БД, и `handle_photo` сначала уводил фото в `_handle_chat_photo` (Cursor описывал картинку как мем), хотя ученик ждал именно проверки. Технически — флаг **`_AWAIT_PHOTO_ANSWER`**, который ставится в callback `answer_photo` и проверяется в `handle_photo` **до** chat-роутинга; при наличии профиля с `homework_complete` chat-ветка пропускается. **Флаг переживает альбом** — не снимается на каждом фото `handle_photo`, иначе фото 2..N media-group уходили бы в `/chat` (баг с GDZ-альбомом). Снимается только при явной навигации: `/start`, `/textbook`, `/chat`, «Назад», «Сменить задание», «Ответить текстом». Тесты — `tests/test_homework_photo_priority.py` (включая отдельный тест на альбом из 3 фото)
- **Голосовой ответ на ДЗ**: голосовое сообщение на этапе «Напиши решение или ход задачи» (флаг **`_AWAIT_TEXT_ANSWER`**) теперь распознаётся через STT и **сразу** уходит на проверку через `_run_homework_text_answer_check` — той же веткой, что текстовый ответ. Бот не ждёт подтверждения от ученика. Раньше при активной `/chat`-сессии распознанный голос ошибочно уходил в чат-бот вместо проверки задания. Маршрут homework имеет приоритет над `/chat`; вне обоих режимов голосовые по-прежнему тихо игнорируются. Логика скачивания/STT/превью вынесена в общий хелпер **`_stt_transcribe_voice_message`**. Тесты — `test_handle_voice_homework_route_*` в **`tests/test_chat_voice.py`**

- **Whisper STT в Docker (`tgzh-stt`)**: новый сервис в `docker-compose.yml` — образ **`hwdsl2/whisper-server`** (faster-whisper, OpenAI-совместимый POST `/v1/audio/transcriptions`), `restart: always`, том **`tgzh-stt-models`** для кэша моделей, хост-порт `127.0.0.1:9100->9000` для отладки. Дефолты: `WHISPER_MODEL=small` (хорошее качество русского при ~1.5 ГБ RAM в int8), `WHISPER_LANGUAGE=ru`, `WHISPER_DEVICE=cpu`, `WHISPER_THREADS=4`, `WHISPER_BEAM=1`. `tgzh-bot.depends_on.tgzh-stt: service_started` — не блокирует старт бота. `.env` теперь по умолчанию указывает на локальный сервис: `STT_BASE_URL=http://tgzh-stt:9000/v1`. **README** и **AGENTS.md** обновлены (диаграмма архитектуры, чек-лист, разделы про сервис и параметры `WHISPER_*`)

- **`/chat` — голосовые сообщения**: новый модуль **`stt_client.py`** + хендлер **`bot.handle_voice`** (`MessageHandler(filters.VOICE | filters.AUDIO, ...)`). Голосовое в **`/chat`** скачивается, отправляется на OpenAI-совместимый POST **`/audio/transcriptions`** (Whisper-контракт), распознанный текст показывается в превью **«🎙 Распознано: «…»»** и уходит в **`_handle_chat_user_message`** как обычный пользовательский промпт — со всем сохранением истории, dialog_id-upsert и sleep-памятью. Вне **`/chat`** голосовые тихо игнорируются. Конфиг — env-блок **`STT_*`** (**`STT_BASE_URL`**, **`STT_API_KEY`**, **`STT_MODEL`** default `whisper-1`, **`STT_LANGUAGE`** default `ru` / `auto`, **`STT_TIMEOUT_S`**, **`STT_MAX_AUDIO_BYTES`**); если **`STT_BASE_URL`** пуст — фича выключена и бот вежливо сообщает. Содержимое распознавания не логируется (только метаданные). Метрика **`tgzh_stt_requests_total{outcome}`**. Тесты — **`tests/test_stt_client.py`** и **`tests/test_chat_voice.py`**

### Security

- **Очистка чувствительных данных в репозитории**: удалён `cursor.settings.json` с proxy-credentials из git (добавлен `cursor.settings.json.example`, файл в `.gitignore`); реальные хосты и абсолютные пути разработчика в коде и документации заменены на плейсхолдеры; URL страницы привязки hub вынесен в **`MOTOK_LINK_PAGE_URL`** (fallback: **`MOTOK_HUB_URL`** + `/link`)

- **`CHAT_SAFETY_POLICY` (нерасторжимый префикс `/chat`)**: константа в **`ai_checker.py`** и синхронный дубль **`bot._CHAT_SAFETY_POLICY`** (тест **`test_bot_and_server_safety_policy_are_in_sync`**). Префикс всегда идёт поверх **`CHAT_SYSTEM_PROMPT`**, через env не отключается. Актуальная структура: **п.0** — обязанность обрабатывать **multimodal-контент** текущего сообщения (картинки, base64, временные пути bridge вроде `/tmp/cursor-openai-sandbox/...`); запрещены отказы «только OCR», «не могу по пути», «прикрепите фото» при реально переданном вложении; **п.1** — запрет shell/листинга/чтения произвольных файлов, env, сети; **п.2** — чтение только конкретного вложения по пути от bridge, без соседних файлов и без свечения абсолютных путей в ответе; **п.3** — отказ на просьбы из п.1 фразой «Не могу: разрешено только обычное общение и разбор того, что вы прислали в сообщении»; просьбы «посмотри фото» относятся к п.0; **п.4** — не выдумывать результат shell по памяти; **п.5** — без мета-преамбул («сначала загружу инструкции», «теперь посмотрю фото» и т.п.). Тесты **`test_chat_safety_policy_*`** проверяют наличие префикса и подстроки **`multimodal-контент`**.

### Fixed

- **Метка смешанных чисел**: снятие и детект **`[tgzh_mixed_numbers]`** с допустимыми пробелами внутри скобок (как иногда пишет VLM), чтобы метка не попадала в сообщение ученику

- **Текстовый ответ на ДЗ**: если тело приходит без MIME или как **`application/octet-stream`**, по байтам больше не подставляется **`image/jpeg`** для валидного UTF-8 - проверка идет как **`text/plain`** сразу в LLM, без pre-OCR

- **TEI для отзывов**: запросы к **`TEI_SENTIMENT_URL`** / **`TEI_EMOTION_URL`** идут через тот же IPv4-транспорт, что и исходящие HTTP бота (меньше сбоев **All connection attempts failed** в Docker при резолве имени)

- **`feedback_tei`**: восстановлен рабочий модуль после поврежденной правки (значки NLP, **`analyze_feedback_text`** без временного NDJSON-логирования)

- **Дисклеймер под результатом проверки**: короткая фраза курсивом про ошибки нейросети и ручную проверку (без блока про учебник и ГДЗ)

- **Результат проверки**: условие задачи с gdz.ru выводится **в том же сообщении**, что и разбор (блок перед ответом модели), а не дублируется из текста LLM; в промпте убрано требование «вставить условие в ответ» и добавлен запрет на зацикливание одинаковых пунктов списка

- **Меню команд Telegram (Desktop)**: **`set_my_commands`** дублируется с **`BotCommandScopeAllPrivateChats`**; после снятия reply-клавиатуры для чата — **`MenuButtonDefault`**, затем глобально **`MenuButtonCommands`**, чтобы список команд чаще отображался в **Telegram Desktop**

- **PostgreSQL, Telegram `user_id`**: колонки **`user_id`** переведены в **`BIGINT`** (ревизия **`008_user_id_bigint`**): идентификаторы вроде **`5241098336`** больше не дают **`integer out of range`** при записи в **`user_consent`** и остальные таблицы; обновлены **`scripts/postgres_schema.sql`** и **`init_db`** (**`user_storage`**, **`bot_stats`**)

- **Дисклеймер-викторина**: кнопки несут **`DISCLAIMER_VERSION`** в **`callback_data`** (`dc:quiz:{version}:{idx}`); при несовпадении версии - подсказка отправить **`/start`**. Старый формат **`dc:q:{idx}`** по-прежнему обрабатывается. При ошибке записи в БД - понятный алерт; при неверном ответе - запись в лог (**`picked`**, **`correct`**, **`data`**)

- **Docker `tgzh-server`**: в образ не попадал **`homework_check_status.py`**, после импорта в **`ai_checker`** контейнер API падал с **`ModuleNotFoundError`** — проверка фото не работала

- **Alembic в контейнере бота**: **`DATABASE_URL`** вида **`postgresql://...`** переводится в **`postgresql+psycopg://...`**, чтобы SQLAlchemy использовал установленный **psycopg3**, а не несуществующий **psycopg2**; в образ **`tgzh-bot`** копируется **`scripts/postgres_schema.sql`** для миграции **`001_initial`**

### Changed

- **Оглавление ГДЗ, несколько проверочных**: бот и **`POST /check`** передают **`gdz_verif_works`** (подписи проверочных из оглавления, в т.ч. из **`img alt`**); в **`VLLM_PROMPT_GDZ_CHECKLIST`** добавлен плейсхолдер **`{verif_works}`** и указание, что номера в разных работах могут совпадать

- **Условие задачи в промпте проверки**: бот передает **`gdz_task_condition`** в **`POST /check`**; текст условия **вставляется в сообщение «Результат проверки»** перед разбором модели (**`_check_result_task_condition_html`**); в **`VLLM_PROMPT_GDZ_TASK_CONDITION`** по умолчанию модель **не дублирует** условие в своем ответе и получает указание **не зацикливать** повторяющиеся пункты списка

- **Бот, привязка ДЗ**: после выбора упражнения или проверочной (и при текстовом вводе номера) бот публикует **условие задачи** с gdz.ru (**`fetch_homework_check_gdz_data`**, тот же источник, что для **`gdz_task_condition`** при проверке)

- **Промпт проверки**: **`VLLM_PROMPT_IGNORE_GDZ`** по умолчанию явно просит игнорировать на фото и кириллические варианты (**гдз.ру** и т.п.), не только **gdz.ru**

- **Шаг 2 после параграфа**: повторный разбор оглавления gdz.ru для выбранного параграфа — кнопки страниц проверочных (**`стр.N`**, лимит **`GDZ_VERIF_BUTTONS_MAX`**), клавиатура номера упражнения с **префиксной валидацией** по списку номеров из оглавления; при пустом списке упражнений — запасной диапазон **`GDZ_EXERCISE_KEYPAD_FALLBACK_MAX`**; текстовый ввод и «Страница вне списка» сохранены

- **Сменить учебник**: перед выбором класса удаляются вспомогательные сообщения бота под этим экраном (промпты ДЗ, «Быстрые команды», выдача GDZ и т.д.) и убирается reply-клавиатура; то же при `/start` и `/textbook`

- **Обратная связь при ожидании**: пока идет долгая операция, в чате обновляется «печатает»; уточнен текст при проверке фото; то же при «Показать решение», сохранении задания, выборе учебника и переходе ко 2 шагу ввода

- **Кнопки «Назад»**: на выборе класса после `/textbook` - «Назад в меню»; в каталоге учебников - «Назад» к классу; при вводе параграфа и упражнения/страницы - шаг назад по сценарию; после «Показать решение» - сообщение с главным меню
